## 一、一句话

这一轮不是"加功能"，是**把「看起来做完了」和「真的做完了」分开**。
17 个版本、15 次真机反馈、6 个只有真机才能暴露的 bug——其中 4 个属于同一类：
**界面说成功了，后端其实没做；或者后端做了，界面不知道。**

## 二、真机反馈 → 修复对照

| # | 用户原话 | 真因 | 修复 |
|---|---|---|---|
| 1 | 「合同有多文件，只能索引一个或几个，其它没有不索引的选项，这一步走不完」 | 只有「已索引/未索引」两态，切不出条款的附件永远是未索引 | 索引过任意一份即算完成；未索引默认不审 |
| 2 | 「未索引的默认就是不审核的，无需再确认」 | 我加的「必须写理由才能跳过」把逻辑搞复杂了 | 理由改选填，「不索引」降为可选留痕 |
| 3 | 「给修改意见增加批注功能」 | 修订版只有红线，没说为什么改 | Word 批注：条款号 · 风险级别 / 问题 / 建议 / 依据 |
| 4 | 「以批注形式的一般不会有删除的内容」 | 我做成了改正文 + 批注，而对方要的是正文不动 | 默认改成**只批注**；改正文必须显式点 |
| 5 | 「有些条款是批注，有些是修订，用按钮做区别」 | 全局开关，不能逐条选 | 每条意见两个按钮，可混用；措辞自动切「建议改为/建议」 |
| 6 | 「没有看到这 2 个按钮」（×3 次） | ①只改了表单视图②按钮绑在"已登记意见"上③改错了 profile | 全文视图也加；草稿状态也可见；**改用 Workbench profile** |
| 7 | 「这里不要给字数限制」 | 15 字下限逼人凑字 | 取消字数；只要求"至少填一处" |
| 8 | 「已登记过相同问题 N6，请用『更新』」但没有该按钮 | 草稿阶段没有 note id，传不出 updateId → 撞去重 | 重复保存**自动更新**，不再报错 |
| 9 | 「AI 审核时我要能给出提示词；要 AI 怎么审」 | 只有一个空输入框 | 「审核指令」多行框 + 6 个模板；验证指令逐字进提示词 |
| 10 | 「120 秒对大合同不足，不要做时间限制」 | 固定墙钟上限，大合同被掐断后切批反而更慢 | 不设上限；补**真正的取消**（原来取消只改界面） |
| 11 | 「重新审核应该清除原草稿」 | 旧草稿残留会被当成新结论 | 审核第一件事就是清空 |
| 12 | 「AI 没给出意见，说明合同过了？」 | 21 条草稿在库里，界面显示"还没有意见" | 条款号归一（`1` vs `第一条`）；旧索引检测 |
| 13 | 「只有 2 条意见就不能下一步」 | 把"意见少"当缺陷，要求凑数 | 删掉该判据；有草稿未采纳时改推"去采纳" |
| 14 | 「感觉可以不要预检这步」 | 四项核心检查 AI 已全覆盖 | 去掉页签；占位符并入验收的「机器自查」 |
| 15 | 「合同审核不需要核对材料」 | 材料逐份核对对合同案无业务含义 | 合同案只核条款与意见；`~$` 临时文件不再入台账 |
| 16 | 「已打包交付了，还在报跑验收」 | 验收结果只在内存，刷新就忘 | 结果落盘 + 有交付包即视为已验收 |
| 17 | 「出报告那里检查一下」 | **3 条意见的修改方案 = 问题描述**，其中一条把审核指令当成了条文 | 发布前闸门：拒绝出表并逐条点名 |
| 18 | 「交付包存放逻辑是什么？去哪找」 | 无入口，只能去 Finder 翻 | 验收页加「在 Finder 中显示」(`deliver.open`, `open -R`) |

## 三、只有真机能暴露的 bug（值得单独记）

### 1. 环境错位：一直改错 profile（最贵的一个）

本机有两个 DSH Desktop：

| 应用 | profile | lawcase 装法 |
|---|---|---|
| DeepSeek Harness.app | `~/.dsh/profiles/desktop` | `link:` 源码，改完即生效 |
| **DSH Desktop (Workbench).app** | `~/Library/Application Support/dsh-desktop/harness/profiles/web` | **`file:` 冻结的 tgz** |

用户用的是 Workbench，我改的是另一个——**连续 3 次误判成"用户没重启"**。
新增 `scripts/install-workbench.mjs`：打包 → 体检 → 装进 Workbench profile → **校验新功能真的在里面**。
已写进项目记忆。

### 2. 内容指纹对嵌套对象失效

```js
JSON.stringify(v, Object.keys(v).sort())   // 键名数组被当成 replacer
```

replacer 数组只保留顶层出现的键，`{source:{file,locator}}` 被序列化成 `"source":{}`。
后果：**改了事实出处，指纹不变，签字单照样打「已核对」**——等于给事后改证盖章。
改成递归排序后，真机立刻显出：153 条台账里 **97 条**属于「核对后被改」，以前全是绿的。

### 3. 界面调用的接口从来不存在

`material.parse_all`、`material.parsed` 两个 op 一直是"界面在调、后端没有"，
用户点「批量解析」只看到「未知 op」，卡在"11 份但一份没解析"。
新增**契约测试**：从 `client.js` 抓出所有 `call('xxx')`，与 `api.js` 注册的 op 对账。
（写这个测试时我自己的正则漏了无引号的 `async verify(payload)`，差点去补一个已存在的接口。）

### 4. 同一条款两个编号

`clauses.json` 里同时有 `1,2,3`（前言列表）和 `第一条…第十五条`。后果三条：
同一条款渲染两次、意见挂不上、保存时误报重复。
修在索引阶段（`splitClauses`：存在「第X条」体系时数字编号不算条款）+ 界面键归一。

### 5. 取消按钮不取消

去掉 120 秒上限后才暴露：`取消` 只改界面状态，后端请求照跑。
补 `note.aiCancel` + `AbortController`，并加"同一案件禁止并发审核"。

### 6. 一键两处渲染，只改一处

「批注/改正文」按钮第一次只加在登记表单视图，而默认是全文视图——功能对用户等于不存在。
教训：**同一个 UI 有两个实现的地方，测试必须覆盖用户实际会看到的那个，并且用默认参数渲染**。

## 四、新增/强化的机制

| 机制 | 落点 | 判据 |
|---|---|---|
| 写入审计 | `core/audit.js` | 每次写入案件侧 + 插件侧各一条，含会话与前后差异 |
| 案情简报 | `core/brief.js` / `lc_case_brief` | 上次动作 + 卡点 + 三段色，≤15 行 |
| 核对三段色 | `checkStatus().tri` | 绿=核过没变 / 黄=核后又被改 / 灰=从没核过 |
| 发布前闸门 | `buildReport` | 空方案 / 与问题相同 / 混进提示词 → 拒绝出表并点名 |
| 接口契约 | `test/api_ops_contract.test.js` | 界面调的每个 op，后端必须存在 |
| 装机自检 | `scripts/selfcheck.mjs` | 结构/工具/测试/数据/面板，任一 ⛔ 即 exit 1 |
| 一键装 Workbench | `scripts/install-workbench.mjs` | 打包 + 体检 + 安装 + 验证功能真在包里 |

- 「按钮在默认视图里必须出现」← 只改一处会红

- 「改出处必须变 stale」← 旧代码先红后绿
- 「正常意见不能误杀」← 闸门不能过严
- 「没接 sink 时审计必须为空」← 证明检查不是永远通过

## 七、给你的一条操作路径

```
1. ⌘Q 完全退出 DSH Desktop (Workbench) 再打开
2. 打开案件 → 材料页 → 点「批量解析」（这次能跑了）
3. 条款页 → 只索引要审的那几份（其余默认不审）
   ⚠️ 旧案件需点一次「重新索引」清掉脏编号
4. 意见页 → 工具条「审核指令 ▾」写要求 → 「AI 审核全部条款」
5. 逐条处置：批注 / 改正文 / 丢弃（写理由）
6. 验收页 → 「跑五道验收」→「打交付包」→「在 Finder 中显示」
```
