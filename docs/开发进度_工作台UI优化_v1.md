# LawCase 工作台 UI 优化 · 开发进度 v1

日期：2026-10-26　｜　版本：lawcase **2.22.1**（365 测试全过）
起点：2.21.0 的客户端半区 `lib/client.js`（工作台 + 插件面板共用同一份 Panel）
约束：不改业务逻辑、不改 API 与字段语义、不改权限规则、不引入新依赖。

> 2.22.1 是按 `/draw-ui` 对现有工作台做的视觉优化版：延续宿主主题 Token，
> 将界面方向收敛为「法律案件操作台」——浅色层次、白色内容面、明确的品牌主操作、
> 轻量边框和阴影、紧凑但不拥挤的状态导航。真实业务流程与权限不变。

## 一、做了什么

只动一个文件的核心：`lib/client.js`。全部改动集中在表现层。

### 1. 窗口布局

| 改动 | 位置 | 目的 |
|---|---|---|
| `UiStyles` 组件内样式 | 组件树内 `<style data-lawcase-ui>` | 卸载工作台自动清理，不污染宿主 |
| `.lawcase-side` 改为 `flex: 0 1 clamp(240px, 24vw, 320px)` | 侧栏 | 宽度随窗口伸缩，长路径不撑破 |
| `.lawcase-body` 在 ≤980px 转 `column` | 主分栏 | 中等宽度下侧栏上移，主区不被挤压 |
| `.lawcase-side` 窄屏限高 250px | 侧栏 | 防止案件列表吃掉正文 |
| `.lawcase-tabs` 横向滚动 + `.lawcase-tab` 不换行 | 页签行 | 7 个页签在窄屏不换行撑高 |
| `.lawcase-toolbar-root` 窄屏独占一行 | 顶栏 | 案件根目录路径可见且不挤按钮 |
| `.lawcase-notice` `max-height: 96px` + `overflow: auto` | 结果条 | 长报错可滚动，不破版 |
| `.lawcase-ai` 绝对定位覆盖层 | AI 对话抽屉 | 默认不占位；点击「打开 AI 对话」才显示，关闭后工作区恢复 |
| 案件标题区 `position: relative/z-index` + 窄屏换行 | 案件标题/标签 | 防止 compact 宿主层或长标题遮住案件标签 |
| `scroll` 增加 `flex: 1` | 主内容区 | 保证底部状态栏不覆盖事实卡片 |
| 底部状态条文字改为可换行 | 卡点/下一步 | 长文案不在窄屏压住按钮 |
| 核对阶段按 `checkoff.kinds` 选待核页 | 下一步 | 事实已完成时跳材料/结论，不再事实页空转 |

### 2. 按钮

| 改动 | 说明 |
|---|---|
| `Button` 加 `className`（`lawcase-button` / `-primary` / `-danger`） | 悬停、聚焦、点击样式集中管 |
| 高度从 3px/9px padding 提到 `min-height: 32px` | 点击目标够大 |
| 主按钮加粗 + `minWidth: 72` | 主次层级一眼可分 |
| 新增 `kind: 'danger'` | 作废类操作统一标红 |
| `:focus-visible` 品牌色轮廓 | 键盘可见焦点 |
| `aria-busy`、`data-dsh-no-drag` | 语义 + 宿主不误拖拽 |
| `@media (prefers-reduced-motion: reduce)` | 关掉过渡动画 |

### 3. 任务提示

| 场景 | 处理 |
|---|---|
| 进行中 | 顶栏下方 3px 品牌色进度条 + 隐藏文案 `role="status"` |
| 加载 | 保留原「读中…」「预筛中…」按钮文案 |
| 空状态 | `Empty` 加 `role="status"` + `aria-live="polite"` + 虚线框 |
| 异常 | 页内错误 `role="alert"` + `aria-live="assertive"` + 自动换行 |
| 重试 | `runAction` 失败时把原 `(label, op, payload, after)` 存进 `notice.retry`；`Notice` 渲染「重试」按钮，重跑同一 op |

### 4. 结果提示

| 场景 | 处理 |
|---|---|
| 成功 | 绿色 `role="status"`，保留操作名 + 摘要 |
| 失败 | 红色 `role="alert"`，带「重试」 |
| 部分成功 | 批量核对的 `failed` 列表原样展示，不折叠 |
| 长文本 | `overflowWrap: anywhere` + `max-height` 滚动，`title` 保留全文 |

## 二、覆盖的界面状态与边界

- 未设案件根目录 / 案件列表为空 / 列表很长
- 未选中案件（空态引导页）
- 材料 / 事实 / 结论 / 工序 / 条款 / 意见 / 预检 / 验收 各页空数据
- 操作进行中、成功、失败、部分失败
- 超长路径、超长错误、超长案件标题
- 1280–1920px、980–1280px、≤640px 三档宽度
- 键盘 Tab 全链路、禁用按钮、危险操作

## 三、验收标准

**布局**
- 桌面宽度下侧栏与主区互不挤压
- ≤980px 侧栏上移，主区不被压扁
- 窄屏工具栏与页签不裁切、不横溢

**按钮**
- 主/次/危险三级可辨识
- 悬停、点击、禁用、处理中、键盘焦点五态都有视觉反馈
- 「作废事实」仍必须填理由，未填时按钮禁用

**任务提示**
- 进行中状态不丢失（进度条 + 按钮文案双通道）
- 错误带原因，且能就地重试
- 部分失败不会被显示成整体成功

**结果提示**
- 成功/失败颜色与语义分离
- 长文本可滚动，不撑破布局

## 五、取舍与优先级

| 优先级 | 项 | 理由 |
|---|---|---|
| P0 | 不溢出、状态不丢、失败可恢复 | 直接影响能不能用 |
| P1 | 按钮层级与五态、键盘焦点 | 降低误操作，属于可用性底线 |
| P2 | 窄屏适配、长文本 | 律师多用桌面，窄屏是兜底场景 |

**没有做的事**（有意为之）：

- 没引入任何 UI 组件库或新依赖 —— 宿主 token + 手写控件足够。
- 没把 `Notice` 改成浮层 toast —— 现位置在操作条与标题旁，不遮挡内容，改动风险大于收益。
- 没做主题切换 —— 沿用宿主 `--dsw-alias-*` 变量，深浅色自动跟随。
- 没动任何 op、字段、权限 —— 本轮零业务改动。

## 六、已知限制

- `color-mix()` 用于危险按钮的悬停底色，Safari 16.2 / Chrome 111 以下不生效，会退化为无底色（不影响可点击性）。
- 窄屏断点 980px / 640px 是经验值，没有真实设备矩阵测试。
- AI 抽屉的窄屏覆盖模式（`position: absolute`）只在 customFrame 工作台里生效，
  普通面板模式由宿主任左侧常驻会话，不经过这段代码。
