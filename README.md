# LawCase 使用说明（律师版）

适用版本：**2.57.0**（65 个工具 +「律案」面板 / 工作台）

阅读对象：承办律师、律师助理。本文只讲**怎么用**；安装、升级、排障找 IT，开发文档见仓库 `docs/`。

> **两种用法，共用同一套台账**
>
> - **对话式**（本文主线）：在对话框里说「下一步做什么」，助手调工具。
> - **面板式**（2.9 起）：左栏「律案」图标 → 案件列表 + 台账页签，顶部一行操作条。
>   新建案件只填**案件名称**即可：目录名按名称自动生成并落在案件根目录下。
>   案型下拉显示中文（诉讼/争议、合同审核），落盘仍是对应的英文值。
>   DSH Desktop 里则是一个独立「工作台」，走同一套数据。

## 〇、这一版改了什么（2.42 → 2.57）

> 如果只看一段，看这张表。每一条都对应一次真机反馈。

### 合同审核：从「走不完」到「能交付」

| 问题（真实反馈） | 现在 |
|---|---|
| 「索引条款这一步始终走不完」 | 索引了哪几份就审哪几份；**未点索引的默认不审**，不需要再逐个确认 |
| 「未索引的默认就是不审核，无需再确认」 | 每份合同旁有可选的「不索引」标记，只为留痕，不挡路 |
| 「只能索引一个或几个，其它没有不索引的选项」 | 一份都不索引时会提醒；索引过任意一份即算完成 |
| 「同一条款有两个编号，意见挂不上」 | 索引阶段就排除前言里的 `1、2、3`；旧索引会被检测出来并提示重建 |

### 意见与批注

| 问题 | 现在 |
|---|---|
| 「给修改意见增加批注功能」 | 生成的 Word 带右侧批注框：**条款号 · 风险级别 / 问题 / 建议改为 / 依据** |
| 「有些条款是批注，有些是修订」 | 每条意见两个按钮：**批注**（正文一个字不动）／**改正文**（画红线）。默认批注 |
| 「这里不要给字数限制」 | 取消 15 字下限，只要求「问题与条文至少填一处」 |
| 「已登记过相同问题，请用『更新』」但根本没有该按钮 | 重复保存**自动更新**那一条，不再报错 |

### AI 审核

| 问题 | 现在 |
|---|---|
| 「AI 审核时我要能给出提示词，要 AI 怎么审」 | 「审核指令」多行框 + 6 个常用模板（只看不利条款 / 逐条给替代表述 / 重点查三处…） |
| 「120 秒对小合同够，大合同不足」 | **不设墙钟上限**；随时可「取消」，取消会真的中止后端请求 |
| 「重新审核应该清除原草稿」 | 点审核的第一件事就是清空旧草稿（否则上次残留会被当成新结论） |
| 「AI 没给出意见，说明合同过了？」 | 有 AI 草稿未采纳时，卡点提示「AI 已审出 N 条，一条都没采纳」 |

### 界面与流程

| 问题 | 现在 |
|---|---|
| 「感觉可以不要预检这步」 | **去掉预检页签**；占位符检查并入验收页的「机器自查」 |
| 「合同审核不需要核对材料」 | 合同审核案**不核材料**（诉讼案仍逐份核对卷宗） |
| 「还在提示跑验收（已跑过）」 | 验收结果落盘；有交付包即视为已验收，不再重复催 |
| 「出报告」 | 加**发布前闸门**：修改方案为空/与问题相同/混进提示词原话 → 拒绝出表并点名 |
| 「交付包去哪找」 | 验收页加「**在 Finder 中显示**」，直接定位最新交付包 |

### 给 IT 的两件事

- **写入审计**：每次写入案件侧 `.lawcase/log.jsonl` 与插件侧 `.lawcase-plugin/audit/` 各记一条；
- **装机自检**：`node scripts/selfcheck.mjs` 一条命令看结构/工具/测试/数据/面板五项，不过就 `exit 1`。

> ⚠️ **升级后第一次打开，核对分布可能变**：历史数据里本来就有「核对后又被改」的条目，
> 以前看不见，现在被算出来了。这不是新增的问题，是终于显示出来了。

---

LawCase 不替你判断法律问题。它做的是**记账**：把你手上这堆材料变成一套可追溯、可验收的台账——
哪份文件是第几版、每句事实出自哪一页、每条意见挂在哪一条、哪一步还没做完、能不能对外发。
判断仍然由你下，但每一步都有痕迹，别人接手也能接着走。

一句话理解它和助手的配合：

- **插件管格式**：编号（M1、F1、N1、P1）、出处、版本、状态机、验收清单、交付包。这些不靠记性也不靠自觉。
- **助手管内容**：读懂材料、提炼事实、写意见、找法条、扮演反方攻击你的结论。
- **你管拍板**：定哪版为准、事实是否属实、结论是否成立、意见是否够狠、能不能外发。

## 一、五分钟上手

做三件事，剩下跟着助手走。

**第 1 步｜给它一个空文件夹当「案件目录」**

产出全部写在这个目录里，建议一案一空目录：

```
/Users/你/Documents/案件/2026-某某公司诉某某公司
```

**第 2 步｜告诉它卷宗在哪**

卷宗（PDF、Word、Excel、扫描件）放在另一个目录里，插件**只读不写**，不会动你的原件：

```
/Users/你/Documents/卷宗/某某公司诉某某公司
```

**第 3 步｜在对话框里说这句话（照抄，换成你的路径和案名）**

> 帮我开一个案件：目录 `/Users/你/Documents/案件/2026-某某公司诉某某公司`，
> 名称「某某公司诉某某公司买卖合同纠纷」，案由买卖合同纠纷，
> 我方原告。卷宗目录 `/Users/你/Documents/卷宗/某某公司诉某某公司`。
> 先把材料扫进来、能解析的都解析掉，然后告诉我下一步该做什么。

助手会自动建案、登记材料、批量解析，最后给你一张「下一步」清单。之后每一步只需要回一句
**「下一步做什么」**，它会读一遍案件状态再告诉你卡在哪、该用哪个工具、要你补什么。

日常只用到这四句话：

| 你说 | 它会做什么 |
|---|---|
| 「下一步做什么」 | 读案件状态，给卡点和该调的工具、要你补什么 |
| 「这案现在什么情况」 | 摊开全景：工序、事实、材料、待确认项、上次做了什么 |
| 「跑五道验收」 | 五道结果 + 必须修清单（不改任何状态） |
| 「打个包」 | 出交付包；有硬性失败会拒绝，并告诉你缺什么 |

同一个案件的后续动作不用每次重复路径；**只有新开会话**时才需要说一次「打开这个案件：<路径>」。

> 装好或升级插件后要**新开一个会话**，否则助手看不见这些工具。
> 先让助手跑一下 `lc_ping`，返回版本号和 `ok` 就说明通了。

## 二、两种案型，两套验收判据

建案时要说清是哪一种，它决定后面怎么验收、怎么做：

| 案型 | 说什么 | 验收重点 | 主线 |
|---|---|---|---|
| **诉讼 / 争议** | 默认就是这个，不用特别说明 | 事实能不能追到出处、结论有没有引事实、工序走完没有 | 材料 → 事实 → 结论 → 对抗复盘 |
| **合同审核** | 说「合同审核」「审合同」，助手会按 `contract` 建案 | 条款逐条索引过没有、每条意见能不能直接照着改 | 条款索引 → 意见 N1/N2… → 意见表 + 修订版 |

两套判据不能混用：拿诉讼的「事实可追溯」去卡合同审核，永远卡不出东西来（合同案的产出是意见，不是事实）。

## 三、诉讼 / 争议案件怎么走

| # | 这一步做什么 | 你直接说 | 你真正要判断的 |
|---|---|---|---|
| 1 | 建案 | 「按上面说的建案」 | 案名、案由、当事人写得对不对（以后清单和交付包抬头就用它） |
| 2 | 登记材料 + 解析 | 「把材料扫进来并解析」 | 有没有漏案卷；扫描件解析出来是不是乱码 |
| 3 | 定版本 | 「哪几份是同一份文件的不同版本？」 | **哪一版才是准的**（它只列出来，不替你决定） |
| 4 | 拆工序 | 「把这件事拆成工序，每道写验收标准」 | 拆得够不够细、验收标准是不是能用眼睛验 |
| 5 | 登事实 | 「从材料里挑出付款相关的句子，给我逐条核对」 | 这条事实是否属实、定位是否准、有没有断章取义；**核对过的登记时就标「已复核」** |
| 6 | 出结论 | 「基于 F1、F3 出结论」 | 结论站不站得住、引用的事实够不够 |
| 7 | 对抗复盘 | 「开一轮复盘：先攻击，不要给建议」 | 攻击点哪些是真致命、回应是否狡辩 |
| 8 | 五道验收 | 「跑五道验收」 | 标 ⚠️ 的项要不要处理 |
| 9 | 打交付包 | 「把这案打个包，交付对象写合伙人」 | 能不能外发 |

**关键约定：事实必有出处。** 每条事实必须给出处——材料编号（`M1`）+ 定位；原文引用不是必填，
但强烈建议填上（验收会拿它去核那个位置到底是不是这句话）。写不出定位就别登记，留着比编一个更安全。定位这么写：

| 写法 | 含义 | 用在哪 |
|---|---|---|
| `P3` | 第 3 段（含空段，按文档真实次序） | Word / Excel / txt |
| `N2` | 第 2 个**非空**段 | Word |
| `第3段` | 同 P3 | 通用 |
| `第2页` | 第 2 页 | PDF / 扫描件（有页码的才有意义） |
| `表格「应付账款」行` | 位置描述 | 台账类表格 |

定位和引文会被机器复核：**如果解析过的材料里那个位置根本没这句话，验收直接判死**（不是提醒，是不通过）。
这也是它的价值——嘴上的「我记得合同里写了」过不了这一关。

## 四、合同审核怎么走

| # | 这一步做什么 | 你直接说 | 你真正要判断的 |
|---|---|---|---|
| 1 | 建案（合同案型） | 「建个合同审核案，合同在 …」 | 是替哪一方审（甲/乙），审到什么力度 |
| 2 | 条款索引 | 「把合同按条切出来」 | 切得对不对（有没有把附件、落款也切进来） |
| 3 | 逐条出意见 | 「逐条审，指出问题的同时给可替换条文」 | 哪些是真风险、哪些只是措辞偏好、级别给对没有 |
| 4 | 台账体检（可选） | 「买方给的付款表体检一下」 | 日期、金额口径是不是被 Excel 搞坏了 |
| 5 | 意见表 | 「生成意见表」 | 分档是否合理（重大/建议修改/提示） |
| 6 | 修订版合同 | 「出一版带修订痕迹的合同」 | 逐条接受/拒绝，别整篇照收 |
| 7 | 五道验收 | 「跑五道验收」 | ⚠️ 项怎么处理 |
| 8 | 打交付包 | 「打包，交付对象写客户」 | 能不能给客户 |

**每条意见必须四要素齐全**：条款编号 · 问题与后果 · 可直接替换的条文 · 依据。
只写「建议进一步明确」「予以完善」「酌情」「加强」这类话会被**当场拒收**——因为它对客户没有用，对法院也没有用，改稿的人还是不知道写什么。

条款编号必须是合同里真实存在的（合同只有九条，你写「第十条」会被拒，并告诉你一共几条）。

产出在哪：

```
<案件目录>/out/合同审核意见_20261022-211402.md   ← 意见表（文件名带案号前段）
<案件目录>/out/修订版_<合同文件名>.docx          ← 带修订痕迹（红色删除线 + 红字下划线）
```

修订版是**另存**的，原合同不会被改一个字节。在 Word 里逐条「接受/拒绝」，没接受的修订不生效。

### 面板里怎么走（2.10 起，不写提示词也能做）

一个「合同审核」案件可以装**多份合同**——诉讼才是一案一目录，合同审核统一一个目录：

1. 左栏「律案」→ 选那个合同审核案（案型徽标显示「合同审核」，页签自动变成 **概览 / 材料 / 条款 / 意见 / 验收**）
2. 「条款」页：填 docx 路径 → 索引条款（一份一条）。每条旁边标**已登记几条意见**，没标的说明还没审过
3. 「意见」页：
   - 顶部先定**审核口径**：立场（中立 / 甲方 / 乙方）+ 合同类型（通用/采购/服务/租赁）+ 本次补充要求，点「保存口径」。保存后案头徽标上会显示「立场：站在乙方立场｜类型：采购合同」——复核的人不用翻报告就知道这份意见是替谁审的
   - 条款用**下拉选**（不用手打编号），下拉里带着「（N 条）」提示，避免同一处登记两遍
   - 点 **付款 / 验收 / 解除 / 违约** 四个模板之一，会填入「问题 + 替换条文」骨架，你把 〔〕里的内容改成这份合同的实际情况即可（模板文案本身就过了插件的空泛话术校验）
   - **引文**（可选但强烈建议）：从该条款原文里逐字摘抄一两句，≥6 字。改写成同义句会被拒收——这条规则的作用是让意见从「我认为」变成「这句原文导致」
   - 填完点「登记意见」
4. **AI 审核全部条款（2.32 起）**：口径区右侧选「审核模型」（默认跟随 DSH 当前模型），点「AI 审核全部条款」→ 确认一次（会明说合同正文要发给所选模型服务）→ 插件直接调宿主已配置的模型审完全部条款，**不用打开对话框**。
   - 模型输出必须过确定性校验才算数：条款号要真实存在、severity 只能在 high/medium/low、引文必须**在该条原文里逐字出现**、不许空泛话术。不合格的进「校验拒收」，引文没命中的降为「待人工确认」（不能一键采纳）
   - 超时 / 取消 / token 上限 / 模型去调工具 / 非 JSON 一律显示**失败原因**，绝不显示成「没有风险」
   - 草稿里每条两个去处：**采纳（要修改）**→ 填进意见表单并记「已审·需修改」；**丢弃（无需修改）**→ 要求写一句理由，记「已审·无需修改」并留痕。两条都不会覆盖你的正式台账
   - 「生成提示词」「载入 AI 草稿」仍然保留：不配模型、或想让助手在对话里跑，走这两条
   - 每次审核的**实际模型、口径、时间、合同指纹、草稿采纳情况**都记进 `.lawcase/ai-review.jsonl`，交付包第三章会写清
5. **片段级修订（2.32 起）**：只改条款里的那一段话，不整条重写。每行一处，格式 `条款号 | 原文片段 | 替换为 | 理由`
   - 原文片段必须在该条里**唯一出现**；出现两次以上、或两处修改区间重叠、或缺字段——**整批拒绝**，不会产出「改了一半」的合同
   - 先点「校验并预览」看逐处对照，再点「生成修订版」；原合同永远只读，只写 `out/` 下的新文件
6. 「意见」页下方三个按钮：
   - **生成意见表**（Markdown，首页写明口径与引文核对条数）
   - **生成修订版 docx**（带 Word 修订痕迹，在 Word 里逐条接受/拒绝）
   - **修订对照预览**（不生成文件，直接在面板上看「原文删除线 + 新条文武下划线」的字符级对照）
7. 「验收」页顶部的「**机器自查（占位符）**」：点「检查未填占位符」，几十毫秒扫一遍 `____`、`〔…〕`、`待填写`、`XX`、空括号这类没填的空位。不调模型、不改文件。
   > 原来这一步是独立的「预检」页签，2.53 起并入验收——因为条款编号、附件、关键词、签署这几项 **AI 审核已经全覆盖**，多一步点击没有意义。风险判断交给 AI 审核与人工核对。
8. 再点「跑五道验收」→ 「打交付包」→ 「**在 Finder 中显示**」直接定位到交付包

## 五、单件事怎么做（按需查）

### 5.1 材料登记与定版

- 扫的是**目录**，只登记不复制：你的卷宗目录扫描后不会被写入任何东西。
- 每份文件自动编号 `M1 / M2 / M3…`，后面所有出处都引用这个编号。
- 自动识别版本组：文件名以 `更新 / 终稿 / 终版 / 最终 / 最新 / 修订 / 修改 / 定稿 / 副本 / copy / final / new / v2 / (1) / 第二版` 这类结尾的，同扩展名归成一组，只把最高的那版当「最新」。
- 同一份文书的 docx 与 pdf **不算版本冲突**，会标成「同文档多格式」。
- 待定的组会列出来，用「定版」动作指定哪份为准（`lc_material_decide`）。定完记进台账，以后重扫也不会冲掉。
- 想看哪些是旧版：说「只列非最新版本」。

### 5.2 解析（把文件变成可定位的文字）

支持 `docx / xlsx / pptx / pdf / doc / txt / rtf / 图片`。PDF 按内容自动分级，不需要你选：

| 文件情况 | 走哪条路 | 大致速度 |
|---|---|---|
| 文本型 PDF（能选中、能复制文字） | 直接抽文字层 | 秒级 |
| 扫描件 / 图片型 PDF | 优先 MinerU（保留标题层级和表格），还是抽不到字才退本地 OCR | MinerU 约 15 秒/份；OCR 第一份要加载模型（十几秒），之后每页不到 1 秒 |
| Word / Excel / PPT | 直接读结构，段落号、行号、页码都保留 | 秒级 |
| 图片（拍照、截图） | 本地 OCR，整张算 1 页 | 同上 |

- **扫描件 OCR 单份封顶 100 页**（一份 300 页的扫描卷宗能卡住好几分钟）。真被截断会明确告诉你「只读到前 100 页」，不会假装整份都读了。
- **内容没变就不重复解析**（按内容哈希判断），所以「再解析一次」通常几秒钟就回来了；真要重来可以点名强制重解析。
- 解析结果缓存在 `<案件目录>/.lawcase/cache/parse/`，是中间产物，不用管。

### 5.3 事实台账

- 一条事实只说一件事，4～1000 字。太长就拆。
- 登记时可以选择「已复核」：你已经对着原文核过了，就标上；没有就留「待复核」，验收时会提醒（不拦人）。
- 出处要改就修出处（`lc_fact_amend`），**必须写理由**，改动留痕、原始记录不删；改过出处后复核状态会重置，得重新核。
- 来源被推翻（比如那份文件是对方伪造的）就作废这条事实（`lc_fact_revoke`），同样必须写理由，台账里保留「已作废」区。
- 机器可以先从 `.md / .txt / .csv` 里抽候选给你逐条确认（默认只出候选、不写台账）。`.docx / .pdf` 不抽，先解析成文本。

### 5.4 结论台账

每条结论要挂上支撑它的事实编号。这是硬闸门：**不引事实的结论进不了台账**。
引法条的结论还要写清「哪部法、第几条、来源」，只写条号不写原文会被标成「未回源」。

### 5.5 法条核验

- 登记法条：法规名 + 条号 + 条文原文（+ 来源）。
- 来源分四级：北大法宝 > 官网原文 > 公报 > 手工录入。手工录入会被标成「未回源」。
- 核验可以联网取权威原文比对；没装法宝也能用，只是「法条可回源」这一道最多给 ⚠️。
- 超过 30 天没核过的会提醒你重新核。

### 5.6 对抗复盘（三步，顺序不能乱）

| 回合 | 做什么 | 规则 |
|---|---|---|
| ① 攻击 | 只许攻击，不许给建议 | 写「建议补充 / 应当修改 / 可以考虑」会被拒——先找漏洞，别急着修补 |
| ② 回应 | 每条攻击回应一次 | 承认站不住，或说清凭什么还成立；回应是留痕，不能覆盖 |
| ③ 裁定 | 定级：致命 / 重大 / 一般 | 必须先回应才能裁定；判致命或重大必须写理由；**裁定后不能改判** |

机器可以先把结构性缺陷穷举一遍给你（事实未复核、法条未回源、工序未完就出结论……），
但它不替你回应、不替你裁定——自己判自己，对抗就失效了。

### 5.7 台账体检（Excel）

专门防「账做得挺漂亮，但数不对」。每张表出两样东西：

- **点名的坏毛病**：日期被存成序列号（`46085` 其实是某年某月某日，只是没设日期格式）、整张表没有表头——这两类会直接报出来。
- **每一列的取值类型分布**：`数字 / 公式 / 文本` 各几个。金额的浮点尾巴（`480000.00000000001`）、
  文字算式（`(189,464,959-174,515,814)×20%` 本质是一串字符，不参与计算）就在这里露出来——
  这两类不会单独报一条，需要你看一眼该列是不是混着好几种类型。

体检**只读**。要改也只改两类「改了不改变含义」的（浮点四舍五入到分、日期序列号加日期格式），
而且先给方案、你点头才动，产物另存到 `out/台账修正_<时间>/`，**原文件不动**。
证据目录下的表格一律跳过——改对方提交的证据性质就变了。文字算式、缺表头、列错位它不改，那要判断「本该是什么」。

### 5.8 企业查询（企查查，可选）

按公司名查工商登记、风险、知识产权、经营、董监高、司法案例、标讯等。
结果可以落进案件 `.lawcase/enterprise/`，直接当事实出处引用。

注意：**查询消耗积分**（查询一个主体每月有封顶）。先看有哪些工具（不花积分），确定要查再查。

### 5.9 把一次审核沉淀成 Skill（可选）

审完一个案子，把这次的审查清单固化成公司级 Skill：检查项不超过 12 条，每条写清「检查什么」和「什么算不过」，
再配 3 条以上禁区。下次同类合同直接套。发布后跑三测（可执行性 / 口径唯一 / 禁区可判定），三项全过才算能用。

### 5.9b 每条意见：批注还是改正文

一条意见落到 Word 里有两种形式，**按条款分别选**：

| 按钮 | 正文 | 批注 | 用在哪 |
|---|---|---|---|
| **批注**（默认） | **一个字不动** | 「问题 / 建议改为 / 依据」 | 对外发意见稿——改不改由客户定 |
| **改正文** | 原文划红线 + 新文下划线 | 「问题 / 建议 / 依据」 | 「我们已改好的稿子」 |

同一份合同里可以混着用：第一条只批注、第二条真改，生成的 Word 里各走各的。

> **默认是批注**不是改正文：替客户改合同正文属于越界，要改必须显式点。
> 只批注时批注措辞会自动写成「**建议改为**」（因为正文还是原样），改正文时写「建议」。

**字数不限**（2.50 起）：问题和条文都不卡字数，只要求「至少填一处」——两边全空的意见没有意义。

**重复保存 = 更新**：同一条款同一个问题再存一次，会就地更新那一条，不会新建也不会报错。

### 5.10 交付包

把散在各处的产物打成一个能直接交给合伙人/客户的目录：

```
<案件目录>/
├── .lawcase/            ← 台账（隐藏，别动）
├── out/                 ← 单个产物，会被反复覆盖
│   ├── 合同审核意见_xxx.md
│   ├── 修订版_xxx.docx
│   └── 核对签字_xxx.md
└── 交付包_20261024-1231/  ← ★ 交付包（每次打包新建，不覆盖旧的）
    ├── 交付清单.md        ← 先看这个：每个文件是什么、SHA256、验收结论、未包含项
    ├── delivery.json      ← 机器可读的同一份清单
    ├── 01_合同审核意见.md
    ├── 02_修订版合同.docx
    └── 03…07 条款索引 / 五道验收 / 进度台账 / 结论台账 / 材料登记
```

**怎么找**：验收页点「打交付包」后，再点「**在 Finder 中显示**」，会直接在 Finder 里选中最新那个交付包文件夹。

> 注意 `out/` 与 `交付包_xxx/` 不是一回事：`out/` 是中间产物（会覆盖），交付包是**快照**（一次一份，之后改了意见表也不会自动同步——要重新打包）。

### 5.11 告诉 AI「这次怎么审」

「意见」页顶部的「**审核指令**」是给 AI 的一次性要求，会随提示词一起发给模型。
懒得想措辞就点模板：

| 模板 | 作用 |
|---|---|
| 只看对我方不利的条款 | 对方占便宜的写法直接给替代表述 |
| 逐条给替代表述 | 不许只说「建议明确」，必须能粘回合同 |
| 重点查这三处 | 付款节点 / 违约责任 / 解除与管辖 |
| 别报格式类小问题 | 只报实体问题 |
| 按风险高低排序 | 最严重的三条放最前 |
| 这是一份要发给对方看的稿 | 措辞克制，不用对抗性形容词 |

指令只是起点，点进去可以继续改。它与上方的「立场 / 类型」叠加生效，不互相覆盖。

> **审核时长**：不设上限（2.51 起）。大合同跑得久是正常的，随时可点「取消」——取消会真的中止后端请求，不只是改界面。

清单里会明写**「所有内容均为初稿，须经承办律师复核后方可对外使用」**，
也会明写「未包含哪些内容」——缺什么就写缺什么，不留空白让人误以为齐了。

## 六、五道验收怎么读

只读检查，**不会**自动把案件标成「已完成」——能不能定稿只能人说了算。

| 案型 | 五道 |
|---|---|
| 诉讼 / 争议 | 事实可追溯 · 法条可回源 · 逻辑自洽 · 格式合规 · 保密可脱敏 |
| 合同审核 | 条款已索引 · 法条可回源 · 意见可执行 · 格式合规 · 保密可脱敏 |

每道的结果只有三种：

| 结果 | 含义 | 怎么处理 |
|---|---|---|
| ✅ 通过 | 这一道没有发现硬伤 | — |
| ⚠️ 待人工确认 | 形式上有，但机器不敢替你说「没问题」 | 看一眼，够用就往下走（会写进交付清单） |
| ❌ 不通过 | 硬性失败 | **必须修**，修完再验收 |

整体结论（verdict）三档：

- `pass`：五道全过
- `needs_review`：没有硬性失败，但有需要人确认的项——**可以出交付包**，清单里会标出来
- `needs_fix`：有硬性失败——**交付包会被拒绝生成**。确要留档，可以强制生成，但清单里的验收结论会写明未通过。

想只看某几道就点名（比如只跑事实和逻辑）。

## 七、会被「拒收」的写法（这不是报错，是护栏）

| 你想写的 | 结果 | 改成什么 |
|---|---|---|
| 「建议进一步明确」「予以完善」「酌情处理」「加强保密」 | 拒收 | 写出**替换后的条文原文**，让改稿的人能直接复制 |
| 一条事实没有材料编号或没有定位 | 拒收 | 补 `M3 · 第12页`；写不出就先别登记 |
| 出处文件不存在 | 拒收 | 先扫材料，或改用真实存在的文件路径 |
| 结论不引用事实编号 | 拒收 | 先登事实，再让结论挂上去 |
| 意见指向合同里不存在的条款 | 拒收 | 核对条款编号（会告诉你合同实际有几条） |
| 攻击里夹带修改建议 | 拒收 | 第一回合只攻击 |
| 裁定级别写成「严重」「较高」 | 拒收 | 只有 致命 / 重大 / 一般 |
| 判致命或重大但不写理由 | 拒收 | 补理由——这条以后要能拿出来解释 |
| 工序没有验收标准 | 拒收 | 写「怎么算做完」 |
| 交付包里有硬性失败 | 拒收 | 先修，或强制生成并接受清单上的红字 |

拦住你的次数，等于少犯的错。

## 八、只有你能拍板的五件事

1. **哪版材料为准**（定版）。不定版，后面引用的出处可能指向旧稿。
2. **每条事实是否属实**（复核）。机器只保证「这句话在第 12 页」，不保证它是真的、是完整的。
3. **结论成不成立**。它要求结论挂事实，但说服力、法律适用仍然靠你。
4. **对抗复盘的裁定**。哪些攻击是真致命，不能让被攻击的一方自己说了算。
5. **能不能外发**。五道全过 ≠ 可以发；插件最高只会把状态标成「需人工复核」。

## 九、保密与数据边界

- **原件不动**：卷宗目录只登记、不复制、不写；合同修订版另存；台账批改也另存。
- **解析在本机**：Word/Excel/PPT/PDF 抽字、扫描件 OCR、MinerU 都是本机进程，**不上传解析服务**。
- **只有你主动查才联网**：企业查询（企查查）和法条权威原文（北大法宝）会联网，且只发查询词（公司名、法规名+条号），不发案件材料。
- **但内容会进入助手上下文**：助手要读懂材料才能抽事实、写意见，这和你把文本直接粘进对话框是一回事。
  涉密案件能不能交给当前这个模型，请按所里的规定确认，别默认它「只在本机」。
- **不自动脱敏**：「保密可脱敏」这一道只**提示**看到了什么敏感信息（身份证号、银行账号之类），
  是否脱敏、怎么脱敏由人定。交付包默认不含对外脱敏版。

## 九·五、Windows 环境建议

> 这一节是给 IT 和 Windows 用户看的。macOS 用户可跳过。

### 必装（缺了哪些功能会受限）

| 工具 | 用途 | 缺了会怎样 |
|---|---|---|
| **Node.js 18+** | 宿主运行 | 装不起来 |
| **Microsoft Word**（或 WPS） | `.doc` 老格式转换、修订版/批注的最终查看 | `.doc` 无法解析，会提示「另存为 .docx」；`.docx` 不受影响 |
| **Git for Windows** | 仅开发/部署需要 | 普通使用不需要 |

### 选装（装了体验更好）

| 工具 | 用途 | 缺了会怎样 |
|---|---|---|
| **Python 3** | 扫描件 OCR、MinerU 版面解析 | 扫描件只走本地 OCR（散字多、表格乱），能读但不精细 |
| **pdftotext**（poppler） | PDF 文本层抽取 | 退回内置解析，速度慢一些 |
| **PowerShell 5.1+** | 系统自带，`.doc` 转换靠它调 Word COM | Windows 10/11 默认就有 |

### 三条平台差异（容易踩）

**1. 路径分隔符与盘符**
路径统一用绝对路径。Windows 写法是 `D:\案件\2026-某某公司诉某某公司`，不要写 `~\`、不要写「桌面上那个文件夹」。
放在 OneDrive/坚果云同步目录里可以，但必须是**已下载到本机**的状态——「按需下载」会让文件读不到。

**2. 非法文件名字符**
合同原名里如果有 `: * ? " < > |`，在 macOS 上合法、在 Windows 上写不进去。
插件现在会自动把这类字符换成 `_`（见 `lib/core/filename.js`），但你**自己命名卷宗文件时**也建议避开这几个字符。

**3. `.doc` 老格式**
- **macOS**：用系统自带 `textutil`，无需安装任何东西；
- **Windows**：通过 PowerShell 调 **Word COM** 转换，所以**必须装 Word**。
  没装时会明确提示「用 Word 打开后另存为 .docx」，不会静默失败。

> 实务建议：**扫描卷宗时就统一转成 `.docx`**。`.doc` 是 97-2003 的老二进制格式，解析依赖 Word，跨平台最容易出问题。

### 目录与权限

- 案件目录建议放在**本地盘**（如 `D:\法律案件\`）或已完全同步的云盘目录；
- 不要让路径里出现 `#` `%` `&` 这类符号（某些工具的命令行会截断）；
- 全路径长度控制在 **260 字符以内**——Windows 的路径上限，中文算字节更容易超。插件会自动缩短过长的产出文件名，但案件根目录的层级请自己控制。

### 验证安装是否正常

在插件目录下运行：

```bat
node scripts\selfcheck.mjs
```

它会逐项检查：结构 → 工具注册 → 测试 → 数据可写 → 面板根目录，任一 ⛔ 就非零退出。
Windows 上重点看 **「审计目录可写」** 与 **「面板根目录」** 两项——这两项最容易因为权限或盘符问题失败。

## 十、常见问题

**助手说没有 `lc_` 开头的工具**
插件没加载，或者这个会话是在安装/升级之前开的。先新开一个会话再说；还不行找 IT 看两处日志：
`/tmp/lawcase-boot.log`（模块有没有被加载）、插件包下 `.lawcase-plugin/plugin.log.jsonl`（工具注册成没成）。

**路径怎么写**
一律写绝对路径，从 `/Users/` 开始。不要写 `~/`、不要写「桌面上那个文件夹」。
放在同步盘里可以，但那个文件夹必须是「已下载到本机」的状态——「按需下载」会让文件读不到。

**验收的事实道一直红**
按顺序看：事实台账是不是空的（空的必红）→ 出处写的位置里到底有没有那句话（对不上必红）→ 有没有引用已作废的事实。
修完再验收，不用重建案件。

**「未复核」的 ⚠️ 消不掉**
复核标记只在**登记那一刻**写入（登记时明确「我已经对过原文」）。已经登记为待复核的事实，事后核对完不会自动变——
所以实务做法是：先让助手把候选事实摆出来，你逐条对着原文核，**核完再正式登记并标「已复核」**。
另外，事后修过出处的事实会被重置为待复核（改过出处就得重新核，这是设计）。这类提醒只算 ⚠️，不拦交付，
交付清单里会列出「待复核」条目提醒复核人。

**交付被拒**
先看「必须修」清单。真需要留档（比如给内部看的阶段性版本），可以强制生成；清单里的验收结论会写明未通过，
别把这个包当成能外发的版本。

**PDF 解析出来是乱码 / 只有散字**
先分清是哪种 PDF：能选中文字的走文本层，不会乱；扫描件才走 OCR，出来就是一行行散字（顺序和表格都可能乱），
这是 OCR 的本来水平。需要按页精确指认出处、或者要看表格结构，让 IT 装并启动 MinerU（约 15 秒/份，版面好得多）。
扫描件超过 100 页会被截断，会提示你只读了前 100 页。

**解析很慢**
第一次慢是正常的（MinerU 要加载模型）。之后内容没变的文件会走缓存，几乎是秒回。

**企查查查询失败**
多半是没初始化或 Key 过期。先跑一次探测（`lc_enterprise_probe`），它会告诉你下一步该做什么。

**案件能换电脑吗**
整个案件目录拷走就行：台账都是纯文本/JSON，`out/` 和交付包里是成品。

**能两个人同时改一个案子吗**
不建议。台账是追加式文件，同时写容易互相盖。要并行就各自开副本，最后人工合并。

## 附录 A 工具速查（想点名工具时用）

平时说人话就够了；要精确指定时，用下面这些名字。

**案件与总览**

| 工具 | 干什么 |
|---|---|
| `lc_ping` | 自检：装没装、版本、能否写盘 |
| `lc_case_new` | 建案（案名/案由/当事人/案型/卷宗目录） |
| `lc_case_open` | 开工复述：工序/事实/材料/待确认/上次操作/下一步 |
| `lc_case_status` | 紧凑全景，适合写进汇报 |
| `lc_case_pipeline` | 一键：建案 → 扫材料 → 批量解析 → 报出剩什么要人定 |
| `lc_case_next` | 不知道从哪开始就跑它：给出卡点和可直接调用的下一步 |
| `lc_case_brief` | 一句话简报：上次动作 + 当前卡点 + 核对三段色（给人和给开场注入用） |
| `lc_case_verify` | 五道验收（只读，不改状态） |
| `lc_deliver` | 打交付包（有硬性失败会拒绝） |

**工序**

| 工具 | 干什么 |
|---|---|
| `lc_proc_plan` | 提交工序表（每道必须有验收标准） |
| `lc_proc_update` | 推进状态：待做/进行中/完成/阻塞 |
| `lc_proc_list` | 看进度与「现在可以开工」的工序 |

**材料**

| 工具 | 干什么 |
|---|---|
| `lc_material_scan` | 扫卷宗目录、编号、识别版本组（只登记） |
| `lc_material_list` | 看清单；可只看非最新版 |

| `lc_material_parse` | 解析单份 |
| `lc_material_parse_all` | 批量解析（可按扩展名、限条数） |
| `lc_material_parsed` | 看已解析了哪些、各多少段 |

**条款索引（合同审核）**

| 工具 | 干什么 |
|---|---|
| `lc_clause_index` | 把 docx 按「第X条」切成条款；传材料编号即可，不用查路径 |
| `lc_clause_candidates` | 列出可索引的 docx，标出哪些已索引 / 明确不索引 |
| `lc_clause_skip` | 标记「这份不索引」（未索引本来就不审，标记只为留痕） |
| `lc_clause_unindex` | 取消某份合同的条款索引 |

**事实 / 结论 / 法条**

| 工具 | 干什么 |
|---|---|
| `lc_fact_add` | 登一条事实（出处必填） |
| `lc_fact_list` | 看台账；可只看待复核 |
| `lc_fact_draft` | 从 md/txt/csv 抽候选（默认不写台账） |
| `lc_fact_amend` | 修出处/引文/表述（必写理由） |
| `lc_fact_revoke` | 作废一条（必写理由，保留痕迹） |
| `lc_finding_add` | 登一条结论（必须挂事实编号） |
| `lc_finding_list` | 看结论的事实/法条引用是否还有效 |
| `lc_law_add` | 登法条（法规名+条号+原文+来源） |
| `lc_law_list` / `lc_law_verify` / `lc_law_probe` | 看法条台账 / 核验一条 / 探测法宝是否可用 |

**对抗复盘**

| 工具 | 干什么 |
|---|---|
| `lc_review_open` | 开一轮，指定复盘对象 |
| `lc_review_auto` | 机器穷举结构性缺陷，生成攻击点 |
| `lc_review_attack` / `lc_review_reply` / `lc_review_verdict` | 攻击 / 回应 / 裁定 |
| `lc_review_list` | 每轮攻-应-裁进度与未闭环项 |

**合同审核**

| 工具 | 干什么 |
|---|---|
| `lc_clause_index` | 按「第X条」切条款索引 |
| `lc_note_add` | 登一条意见（四要素 + 可选逐字引文） |
| `lc_note_list` / `lc_note_delete` | 看 / 作废意见 |
| `lc_precheck` | 预检：占位符/编号/附件/关键词覆盖/签署（不调模型） |
| `lc_contract_config` | 读/写审核口径：立场、合同类型、补充要求 |

## 附录 B 案件目录里都有什么

```
<案件目录>/
  .lawcase/              台账（纯文本，可拷可查；不要手改）
    case.json           案件元数据 + 工序表（程序以它为准）
    progress.md         进度台账（人读）
    conclusion.md       结论台账（人读）
    facts.jsonl         事实台账
    findings.jsonl      结论台账
    laws.jsonl          法条台账（含回源状态）
    materials.json      材料登记
    材料登记.md          材料清单与定版结果（人读）
    clauses.json        条款索引（合同案）
    notes.jsonl         审核意见（合同案，含 apply=批注/改正文）
    note-drafts.json    AI 审核草稿（采纳才进 notes.jsonl；重新审核会先清空）
    ai-review.jsonl     每次 AI 审核的模型、口径、合同指纹、草稿采纳情况
    rulings.jsonl       条款判定（已审·需修改 / 已审·无需修改）
    last-verify.json    最近一次验收结果（刷新界面后不会再忘）
    review.jsonl        对抗复盘记录
    log.jsonl           变更记录（谁在什么时候做了什么）
    cache/parse/        解析缓存（可删，删了重解析）
    enterprise/         企查查查询结果落盘
  out/                   中间产物：意见表、修订版合同、核对签字单（会被反复覆盖）
  交付包_<时间>/           ★ 最终交付物：清单 + 产物快照（含 SHA256，一次一份不覆盖）
```

> **`out/` 与 `交付包_<时间>/` 的区别**：`out/` 是干活时的中间文件，每次生成都覆盖；
> 交付包是打包那一刻的**快照**，之后改了意见也不会自动更新——要重新打包。
> 验收页的「在 Finder 中显示」按钮会直接定位到最新那个交付包。

跨会话接手，第一句话就说「打开这个案件：<路径>」，助手会先把状态摊开再动手——
不需要你复述一遍前面做过什么。
